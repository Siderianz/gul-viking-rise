# Контекст проекта: сайт гильдии Viking Rise

## Назначение

Статический многостраничный сайт для гильдии мобильной игры Viking Rise. Сейчас это рабочий скелет с визуальной стилистикой под викингов, языковым стартовым экраном, разделом гайдов из Excel-документа и страницей структуры гильдии.

## Технологии

- Без сборщика и фреймворка: обычные HTML/CSS/JavaScript.
- Общие стили: `styles.css`.
- Общая логика языка и стартового выбора: `script.js`.
- Рендер гайдов из выгруженных данных Excel: `guide-render.js`.
- Данные гайдов: `guide-data.js`.
- Исходная таблица: `GUL Ultimate Guide.xlsx`.
- Основной язык исходной разметки: русский.

## Страницы

- `index.html` - главная страница и стартовое окно выбора языка.
- `migration.html` - заявка на миграцию.
- `achievements.html` - достижения.
- `media.html` - медиа.
- `guides.html` - гайды на основе Excel-документа.
- `kingdom.html` - структура гильдии: R5 и R4 состав.
- `contacts.html` - контакты и ссылки.

## Ассеты

## Языки

Выбор языка происходит на главной странице через стартовое окно с двумя рунами:

- `ru` - русский.
- `en` - английский.

Выбор сохраняется в `localStorage.guildLanguage`. На главной странице при обновлении стартовое окно появляется снова, чтобы язык можно было выбрать заново. На остальных страницах применяется сохраненный язык или русский по умолчанию.

Переводы задаются в `script.js` через объект `translations`. Элементы с `data-i18n` получают текст из словаря. Для полей ввода используется `data-placeholder-i18n`.

Важно: часть старых страниц все еще переводится через словарь простых текстовых совпадений, а не через `data-i18n`. Надежнее постепенно перевести все повторяющиеся элементы на явные ключи.

## Гайды

`guides.html` подключает:

1. `guide-data.js` - данные, извлеченные из `GUL Ultimate Guide.xlsx`.
2. `guide-render.js` - группировка и визуальный рендер данных.
3. `script.js` - общий язык сайта.

Рендер гайдов группирует данные по смысловым секциям, рисует вкладки листов, карточки, чипы, заметки и таблицы. UI гайдов и названия листов частично локализуются. Содержимое самой Excel-таблицы в основном остается в исходном языке документа.

## Best Practices и рекомендации

### 1. Централизовать общий layout

Сейчас шапка, навигация и футер продублированы во всех HTML-файлах. Это быстро приводит к рассинхронизации переводов и активных пунктов меню.

Рекомендуется:

- либо перейти на простой генератор статических страниц;
- либо сделать общий JS-компонент шапки/футера;
- либо хранить навигацию в одном конфиге и рендерить ее на каждой странице.

### 2. Перевести все страницы на `data-i18n`

Сейчас надежнее всего переводятся `index.html`, `guides.html` и `kingdom.html`. Остальные страницы частично зависят от перевода по совпадению текста.

Рекомендуется:

- добавить `data-i18n` всем заголовкам, кнопкам, карточкам, футерам и описаниям;
- отказаться от перевода простых текстовых нод через `translatePlainText`;
- хранить все строки только в `translations`.

### 3. Добавить переключатель языка внутри сайта

Сейчас язык выбирается на главной. Для удобства стоит добавить маленький переключатель RU/EN в шапку, чтобы пользователь мог сменить язык без возврата на главную.

### 4. Оптимизировать крупные файлы

`GUL Ultimate Guide.xlsx` весит около 94 MB. Для сайта это слишком тяжело, если пользователь случайно скачивает файл или если он попадет в хостинг-бандл.

Рекомендуется:

- хранить Excel отдельно как downloadable asset;
- сжать или разделить данные гайдов;
- подумать о JSON вместо большого JS-файла;
- не грузить большой файл, если пользователь не открывает раздел гайдов.

### 5. Улучшить доступность

Рекомендуется:

- добавить видимый `:focus-visible` для всех интерактивных элементов;
- проверить контраст текста на темном фоне;
- добавить корректные `aria-label` для рун выбора языка;
- убедиться, что навигация удобна с клавиатуры.

### 6. SEO и метаданные

Для каждой страницы стоит добавить:

- уникальный `meta description`;
- Open Graph теги для Discord/соцсетей;
- favicon;
- `og:image` на логотип или hero-изображение;
- корректный `lang` через JS уже меняется, но базовая разметка остается `ru`.

### 7. Проверка адаптива

Нужно отдельно пройти мобильные ширины:

- 360 px;
- 390 px;
- 768 px;
- 1024 px;
- desktop 1440+ px.

Особенно проверить:

- верхнее меню;
- карточки офицеров;
- вкладки гайдов;
- таблицы внутри гайдов;
- стартовое окно выбора языка.

### 8. Разделить CSS на смысловые блоки

`styles.css` уже довольно большой. Для дальнейшего роста стоит либо структурировать комментариями, либо разделить на:

- base;
- layout;
- navigation;
- language gate;
- guides;
- kingdom;
- forms;
- responsive.

Без сборщика это можно оставить одним файлом, но с четкими секциями.

### 9. Добавить тестовый чек-лист

Перед каждым изменением проверять:

- открывается ли `index.html`;
- кликаются ли руны выбора языка;
- выбранный язык применяется на других страницах;
- все пункты верхнего меню кликабельны;
- гайды открываются и фильтр работает;
- аватарки состава загружаются;
- мобильная верстка не ломается.

### 10. Перевести данные гайдов отдельным этапом

Сейчас интерфейс гайдов локализован, но сама таблица в основном сохраняет исходные английские данные. Если нужен полноценный русский/английский режим, лучше сделать отдельный слой переводов для `guide-data.js` или хранить две версии данных.

## Осторожность при будущих правках

- Не удалять `guide-data.js`, если не пересобирается раздел гайдов.
- Не перезаписывать `assets/officers/*.png` без проверки аватарок.
- Не менять ключ `localStorage.guildLanguage` без обновления `script.js` и `guide-render.js`.
- При добавлении новой страницы подключать `styles.css` и `script.js`.
- Для новых переводимых текстов сразу добавлять `data-i18n` и ключи в `script.js`.
